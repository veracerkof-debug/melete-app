# Как устроена Melete

Карта проекта для того, кто видит его впервые. Сначала замысел (зачем приложение и какие правила из этого
следуют), потом устройство крупными частями, потом — куда читать дальше. Подробности по темам — `docs/tech/`.

## 1. Замысел

Melete — рабочий стол музыканта в телефоне и на компьютере: учёт занятий и набор инструментов (метроном, тюнер,
пианино, пэды, медиатека с дорожками, табы, диктофон, лупер, тренажёры…), которые открываются прямо в занятии.
Цель — чтобы человек больше играл и рос; мера успеха — время **за инструментом**, а не в приложении.

Из этого — правила, которые объясняют почти каждое техническое решение в коде:

| Правило | Что значит для кода |
|---|---|
| **Всё на устройстве** (local-first) | Нет серверов, аккаунтов, аналитики. Данные — localStorage и IndexedDB; обмен — файлом, папкой или в своей сети Wi‑Fi. Сеть — только по нажатию кнопки (и проверка обновления раз в сутки). Политика `index.html` (CSP) не пускает чужие адреса. |
| **Надёжность важнее функций** | Приложение звучит на сцене и пишет репетиции. Звуковые узлы создаются один раз и не переподключаются; таймеры звука — из звукового потока (`audio/clock.js`), а не `setTimeout`; запись пишется на диск кусками; данные не удаляются, если источник «пропал» целиком. Любой сбой — в журнал, не молча. |
| **Пространство работает на функцию** | Рабочая поверхность инструмента занимает всё окно; модуль обязан жить в четырёх размерах окна (`full`, `half`, `quarter`, `strip`). |
| **Жест прежде кнопки** | Общие жесты — `ui/gestures.js`, `ui/hold.js`; карта — `docs/gestures.md`. |
| **Не DAW** | Студия, лупер и запись — базовые: набросать, записать, отдать файл (WAV, стемы, .mid, MusicXML) настоящей программе. |
| **Без давления** | Ритм недельный; нет серий, лент, сравнений. Статистика честная: время засчитывается по признакам игры, записи о занятиях подписаны (`core/integrity.js`). |
| **Открытый код** | GPL‑3.0; зависимости только совместимые (`LICENSES.md`), всё лежит в проекте — без CDN. |

Полный текст принципов и правил работы — `CLAUDE.md`; история решений автора — `DECISIONS.md`.

## 2. Одно веб-приложение — четыре платформы

Весь продукт — одно приложение на **чистом JavaScript** (ES-модули, без фреймворка) и Web Audio, собранное Vite.
Платформы — обёртки вокруг одного и того же кода:

```
                 src/ (JS, CSS, i18n)  ── vite build ──►  dist/
                         │
     ┌───────────────────┼─────────────────────┬──────────────────────┐
  Веб (gh-pages)     Android (Capacitor)     Windows / Linux (Tauri 2)   Демо (src/showcase)
  без тяжёлых       + плагины на Java        + команды на Rust
  моделей           (android/app/src/…)      (src-tauri/src/)
```

Различия платформ собраны в немногих местах: `core/desktop.js` (компьютер), плагины Capacitor (`registerPlugin('…')`
в JS ↔ `…Plugin.java`), команды Tauri (`invoke('…')` ↔ `#[tauri::command]` в Rust). Всё остальное общее.
Подробно — `docs/tech/platforms.md`.

## 3. Слои кода

```
src/main.js ─► core/index.js: boot()           ← собирает приложение (объект app) и рисует экраны
                │
   ┌────────────┼──────────────┬───────────────┬──────────────┐
 core/       core/screens/    modules/<id>/    audio/         music/
 логика      экраны ядра      инструменты      звук           чистая музыка
 без DOM     (DOM)            (через ctx)      (Web Audio)    (без DOM и звука)
   │             │                 │
   └──── ui/ (общие элементы: шторки, жесты, клавиатура) ─── styles/ (токены темы) ─── i18n/ (ru, uz, en)
```

- **`src/core`** — ядро: данные, сессии, статистика, календарь, расписание, напоминания, папка, синхронизация,
  копии, обновления, журнал. Почти всё здесь — **логика без DOM** (чистые функции и «создатели» объектов),
  поэтому покрыто тестами в Node.
- **`src/core/screens`** — экраны ядра: главная, песни, календарь, «Инструменты», панель профиля и настроек, сессия.
- **`src/modules/<id>`** — инструменты. Ядро не знает их внутренностей; модуль получает всё через `ctx`
  (контракт — `MODULE_SPEC.md`). Новая папка — новый инструмент, без правок ядра.
- **`src/audio`** — звуковой движок: один `AudioContext`, шины и микшер, синтезаторы, метроном, эффекты,
  проигрыватели, запись, разбор записей моделями.
- **`src/music`** — теория, ноты, аккорды, табы, MIDI, MusicXML, проект студии: **чистые функции**, сверены тестами.
- **`src/ui`**, **`src/styles`**, **`src/i18n`** — общие элементы интерфейса, тема (CSS-переменные), переводы.

Направление зависимостей: экраны и модули зависят от ядра и ui; ядро не импортирует модули (только реестр
`modules/index.js`); `music` ни от чего не зависит. Модули между собой общаются только через ядро (`ctx.openIn`,
`ctx.shared`).

## 4. Жизнь приложения: от запуска до записи в статистику

1. **Запуск** (`main.js` → `core/index.js: boot`). Первым стартуют журнал и диагностика. Затем: хранилище
   (`store.js` читает `practice.v1` из localStorage), миграции старых настроек, язык и тема, настройки устройства
   (`device.js`, `practice.v1.tools`), звуковой движок (`audio/index.js: createAudio` — объекты есть сразу, а сам
   `AudioContext` создаётся на первом касании), база файлов (`files.js`, IndexedDB), запись, фоновые обработки,
   MIDI, сессия, папка, синхронизация, копии, обновление. Всё складывается в один объект **`app`**.
2. **Экран** (`screens/shell.js`): вкладки внизу (главная, песни, календарь, инструменты…), панель профиля сверху.
   Экраны подписаны на хранилище (`store.subscribe`) и перерисовываются при изменениях.
3. **Инструмент** открывается окном: вне занятия — на весь экран, в занятии — в раскладке окон
   (`workspace.js`: весь экран, половины, четверти, полосы). `core/modules.js` создаёт для модуля `ctx`,
   догружает код модуля (`index.js`, по требованию) и монтирует его в окно.
4. **Занятие** (`session.js`): активная сессия хранится отдельно (`practice.v1.active`) и переживает перезагрузку.
   Время идёт, пока есть признаки игры (`activity.js`: касания, звук приложения, по желанию — микрофон). При завершении
   строится запись о занятии и **подписывается** (`integrity.js: seal`); статистика (`stats.js`) берёт только
   подписанные записи.
5. **Данные уходят** только по воле человека: резервная копия, папка Melete, файл `.melete` команде, синхронизация
   с компьютером в своей сети.

## 5. Данные — коротко

| Что | Где | Модуль |
|---|---|---|
| Песни, занятия, календарь, общие настройки | localStorage `practice.v1` (JSON, `version: 1`, формат прототипа; номер формата — `schema`, шаги — `core/migrate.js`) | `core/store.js` |
| Проекты студии и лупера | IndexedDB `melete-proj` (пишется только изменённый проект) | `core/projstore.js`, `core/store.js` |
| Настройки инструментов этого устройства (микшер, пианино, тюнер…) | localStorage `practice.v1.tools` | `core/device.js` |
| Идущее занятие | localStorage `practice.v1.active` | `core/session.js` |
| Файлы: записи, видео, табы, MIDI, модули Библии | IndexedDB `practice-audio` | `core/files.js` |
| Куски идущей записи | IndexedDB `melete-rec` | `core/recspool.js` |
| Копии на устройстве (7 суточных + перед обновлением) | IndexedDB `melete-snap` | `core/snapshots.js` |

Слияние любых двух копий данных — по `id`, побеждает больший `updatedAt`, удалённое помечено `deleted`, а не стёрто.
На этом одном правиле держатся загрузка копии, папка Melete и синхронизация. Подробно — `docs/tech/data.md`.

`src/core/index.js` (сборка `app`), `src/core/store.js` (данные) и любого простого модуля, например `src/modules/tuner/`.
