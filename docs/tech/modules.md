# Модули-инструменты

Каждый инструмент — отдельный модуль. Ядро не знает, что внутри; модуль не знает, как устроено ядро.
Они говорят только через объект `ctx`. Полный контракт — `MODULE_SPEC.md`; здесь — как это работает и почему.

## Зачем так

- **Новая папка — новый инструмент.** Реестр (`src/modules/index.js`) находит модули сам (`import.meta.glob`);
  правок в ядре не нужно. Личные модули — в `src/modules-local/` (не в репозитории).
- **Сбой модуля не роняет приложение.** Модуль без обязательных полей не подключается: в «Модулях и функциях»
  появляется строка с ошибкой, остальное работает.
- **Быстрый запуск.** При запуске грузится только `meta.js` (название, значок, цвет, размеры, переводы), код модуля
  (`index.js`) — при первом открытии (`entry(...).load()`), модули — по очереди, по одному.
- **Одни правила для всех.** Звук — только через шины микшера, данные — через `ctx.store`, строки — через `ctx.t`,
  журнал — через `ctx.log`. Поэтому микшер, копии, переводы и диагностика работают для любого инструмента.

## Устройство модуля

```
src/modules/<id>/
  meta.js        лёгкое описание: id, name, icon, color, sizes, order, i18n и признаки (session, inner, multitouch…)
  index.js       сам модуль: { ...meta, mount(host, ctx, size), resize(size), unmount(), status?, midiIn?… }
  i18n/ru.json   строки (и uz, en; el — греческое название для «Минимала»)
  *.css          стили модуля (подключаются из index.js)
  …              части модуля
```

Жизненный цикл: `mount(host, ctx, size)` → сколько угодно `resize(size)` (окно сменило размер: `full`, `half`,
`quarter`, `strip`) → `unmount()`. После `unmount` у модуля не должно остаться таймеров, слушателей и звучащих узлов.
Модуль обязан нормально выглядеть во всех объявленных размерах.

Монтирует модуль `core/modules.js`: создаёт `ctx` (`makeCtx(app, mod)`), догружает код, кладёт модуль в окно и
считает время инструмента, открытого вне занятия.

## Что даёт `ctx` (главное)

| Поле | Что |
|---|---|
| `t`, `tn`, `lang`, `num` | строки модуля (нет ключа — строки ядра), множественное число, язык, числа |
| `store` | настройки модуля на этом устройстве (`get`/`set`, кусок `practice.v1.tools`) |
| `data()`, `saveData()` | данные модуля, которые переезжают с человеком (`settings[id]` в `practice.v1`) |
| `audio` | звуковой движок: шины микшера, синтезатор, метроном, `getContext()` (`audio.md`) |
| `mic` | микрофон по запросу |
| `files`, `jobs`, `sendFile(s)` | файлы пользователя (`files.js`), долгие обработки записей, «Поделиться» |
| `songs`, `song`, `updateSong`, `setlists`, `projects` | песни, текущая песня занятия, сет-листы, проекты студии |
| `session`, `pomodoro`, `stopwatch` | состояние занятия и таймеров |
| `openTool`, `openIn(id, данные)`, `mountTool`, `onPlay` | открыть другой инструмент (например, «В лупер» с файлом) |
| `shared` | общий обмен между модулями без прямых импортов |
| `ui`, `fxPanel`, `presets` | общие элементы, панель эффектов, пресеты |
| `midi` | MIDI-ввод и запись игры |
| `log`, `logErr`, `diag` | журнал и счёт диагностики с префиксом модуля |

## Крупные модули изнутри

**Медиатека** (`modules/audio/`). `index.js` — список и плеер: панель видов (волна, дорожки, текст, аккорды —
`chordview.js`: сетка тактов по сильным долям), метки (`marks.js`), шторка «Дорожки и ноты» (режим, разделить,
микшер дорожек на ходу, ноты, в студию; на Windows — текст и шум). Плеер — `audio/stretchplayer.js`, обработки —
`core/jobs.js`. Форматы одной записи (после конвертера) — варианты той же строки (`variantOf`, `formatsHTML`).
Конвертер (`modules/convert/`) — очередь файлов, формат и качество; движок `audio/convert/`: FFmpeg (пакет на телефоне,
встроен на компьютере) или системные кодеки (`convert.js`, `encode.js`, `flac.js`, `containers.js`).

**Студия** (`modules/studio/`, с 06.11.2026 — снова отдельный инструмент; базовая, не DAW). Данные — проект
`music/project.js` в `state.projects`. `playlist.js` — стол дорожек на холсте (клипы, петля, маркеры);
редакторы партий: `steps.js` — ударные, `roll.js` — ноты, `chords.js` — аккорды; `live.js` — клавиши и пэды под
редактором с записью игры; `chordpad.js` — аккордовая панель; `mixer.js` — микшер студии; `record.js` — запись в
дорожку (предпрокрутка, punch-in, дубли), сведение и стемы (`audio/render.js` — тот же секвенсор офлайн), замер
задержки щелчками. Звучит — `audio/sequencer.js`, звуки GM — `audio/gm.js`. Свой инструмент под редактором нот —
`ctx.mountTool` и `ctx.onPlay`. Сверка функций — `docs/studio-parity.md`.

**Лупер** (`modules/looper/`). Петля — `audio/looper.js` (слои с микрофона, умножение, замена, отмена, такты, часы).
`parts.js` — вид «Партии»: редакторы партий студии открываются в шторке лупера (`embedPart`), партии играет секвенсор
по часам петли; «В лупер» из других модулей — `ctx.openIn('looper', { inbox })`.

**Табы, ноты и текст** (`modules/notes/`). Табулатуры и ноты — alphaTab (Guitar Pro, MusicXML, alphaTex), PDF — pdf.js
(`pdf.js`), определение формата файла — `sniff.js`. `live.js` — партия «с игры»: сыгранное, сетка, правка, MusicXML
(`music/livescore.js`, ноты с микрофона — `audio/notein.js`).

## Как сделать свой

Шаблон с инструкцией — `docs/module-template/`. Короткий путь: скопировать папку в `src/modules-local/<id>/`,
поменять `id` и название, запустить `npm run dev` — инструмент появится в «Инструментах». Чек-лист перед тем,
как модуль станет встроенным: четыре размера окна, три языка, звук только через шину, `unmount` чистит всё,
тест на логику (если она есть) в `tests/`.
