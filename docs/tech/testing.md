# Тесты и проверки

Два уровня: **тесты логики** (Vitest, Node, быстро) и **сквозные проверки в браузере** (Playwright, Chromium).
Логика ядра и музыки почти вся без DOM — поэтому большая часть проверяется первым уровнем.

## Тесты логики — `npm test`

`tests/*.test.js`, около 120 файлов и 950+ проверок, идут за секунды. Что в них особенно важно:

| Тест | Что охраняет |
|---|---|
| `parity.test.js`, `audio.parity.test.js` | ядро и звук совпадают с эталоном — прототипом `legacy/practice.html` |
| `compat.test.js` | данные прошлых версий читаются (копии, настройки, раскладки) |
| `integrity.test.js` | печать записей о занятиях и правила подтверждения |
| `voiceleak.test.js` | отпущенный голос отключает все свои узлы (поддельный AudioContext считает связи) |
| `i18nkeys.test.js` | ключи ru/uz/en совпадают, вызванные в коде ключи есть в словаре, в en/uz нет кириллицы |
| `folder.test.js`, `sync.test.js`, `backupparts.test.js` | слияние, зеркало папки, синхронизация, защита от потери |
| `recspool.test.js`, `files.test.js` | запись кусками и восстановление, ошибки базы |
| `fuzz.test.js` | ядро не падает на испорченных данных |
| `registry.test.js`, `modules.test.js` | реестр модулей и контракт |

Приёмы: зависимости передаются аргументами (`createStore({ storage })`, `createFiles({ indexedDB })`,
`createRecorder(app, { spool: memBackend() })`), поэтому в тестах — простые заглушки в памяти, без моков модулей.
Плагины Capacitor в тестах отсутствуют — код проверяет их наличие.

## Сквозные проверки — `npm run e2e`

`tests/e2e/*.spec.js`, около 55 файлов; общее — `tests/e2e/melete.js`: приложение с готовым профилем (без
регистрации), сбор ошибок страницы и консоли (**любая ошибка консоли валит тест**), свободная сессия с нужными
окнами, жесты пальцем и удержание. Сервер Vite поднимается сам (`playwright.config.js`).

В контейнере Claude: `PW_CHROMIUM=/opt/pw-browsers/chromium npm run e2e -- --trace off`. Одну проверку —
`npx playwright test tests/e2e/<файл>.spec.js`. Не запускайте e2e параллельно с `npm test` — сервер разработки может
упасть под нагрузкой, и проверки покраснеют не по своей вине.

## В GitHub Actions

`e2e.yml` — на каждую отправку в `main` и ветки `claude/**`: тесты логики (сборки dev и pre), затем сквозные
проверки; при падении — отчёт Playwright. Красное чинится до того, как автор возьмёт сборку.

Перед выкладкой APK проверяется на эмуляторе (`build/apk-smoke.sh`).

## Правила

- Новая логика — тест в `tests/`; новая видимая функция — строка-проверка в `tests/e2e/`.
- Ошибка, найденная человеком, — сначала тест, который её воспроизводит, потом правка.
- Тест не отключают и не пропускают, чтобы стало зелёным; «флак» — не причина, а повод найти гонку.
- Перед отправкой в `main`: `git merge origin/main`, `npm test`, нужные e2e, сборка (`npx vite build`).
- Ручные инструменты проверки лаунчера (аудит всех стилей, снимки экранов) — `tests/launcher-tools/`; в обычные проверки
  не входят, как запускать — `docs/launcher.md`, раздел «Состояние и хвосты».
