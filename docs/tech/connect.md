# Связь и обмен

Melete работает без серверов и аккаунтов. Данные переходят между людьми и устройствами пятью путями; каждый
включается только по воле человека.

| Путь | Кому | Как | Модуль |
|---|---|---|---|
| Резервная копия | себе | файл JSON в папку Melete или через «Поделиться» | `core/backup.js` (`data.md`) |
| Папка Melete | себе, другим программам | папка на устройстве, зеркало медиатеки | `core/folder.js` (`data.md`) |
| Файл `.melete` | команде | песни, табы, сет-лист одним файлом через мессенджер | `core/share.js` |
| Синхронизация | своим устройствам | телефон ↔ компьютер в одной сети Wi‑Fi | `core/sync.js` |
| Гости, ансамбль, LocalSend | людям рядом | компьютер раздаёт в своей сети | `core/guest.js`, `ensemble.js`, `localsend.js` |

## Google Диск (с 25.11.2026)

`core/gdrive.js`, вход — `core/gauth.js`, ключи — `core/gconfig.js`, страница настроек — `screens/gdrivepage.js`. Своих аккаунтов и сервера нет: Google нужен
только как хранилище своих файлов. Папка `Melete` на Диске видима; право `drive.file` (приложение видит лишь созданное им).
- **Вход:** OAuth 2.0 с PKCE (без секрета, без библиотек Google и CDN). Android: страница входа в системном браузере (плагин `GAuth`),
  возврат — схема `com.googleusercontent.apps.<ключ>:/oauth2redirect` (intent-filter; схему подставляет `build.gradle` из `gconfig.js`) → `appUrlOpen`.
  Токены — `melete.gauth` (на устройстве; в копию и на другие устройства не идут). Компьютер (loopback `127.0.0.1`) и веб — не сделаны.
- **Раскладка:** `Melete/` — файлы медиатеки под своими именами (свойства `appProperties`: `i` id, `s` размер, `h` хэш сведений, `k` ключ производного),
  `Melete/_melete/data.json` — данные (части `SYNC_PARTS`, слияние `applyParts`), `m-<id>.json` — сведения файла (разбор, текст, привязки).
- **Обмен** (`driveSyncNow`): данные слить к себе и положить объединённое (сравнение по каноническому тексту `canon`: время правки и порядок
  записей не в счёт, иначе устройства переписывали бы файл по кругу); файлы — `planFiles` (трёхстороннее сравнение по `melete.gdrive.ids`),
  куски по 2 МБ (возобновляемая загрузка, `Range` при чтении), повторы при сбоях сети. Удаление на Диске — в корзину Диска; у себя — после
  сверки. Защита: пустой список при непустом прошлом или недоступная база файлов — «недоступно», удалений нет (поэтому удаление последнего
  файла на другое устройство не переносится — файл вернётся на Диск). Перед слиянием — копия (`snapshots.take('sync')`, не чаще раза в 6 часов).
- **Когда:** при запуске (через 15 с), при возвращении в приложение, после правок (через 2 мин) и раз в 15 мин; только в тишине (`app.auto.quiet`), только
  при сети; сбой — реже (до часа), вход слетел — ждёт, пока человек войдёт. Переключатель — `settings.gdrive` (по умолчанию вкл, пока есть вход).
- **Не сделано / не проверено на устройстве:** вход на Android с настоящими ключами, большие файлы по мобильной сети, Windows/Linux, веб,
  шифрование (Google видит содержимое — сказано в политике, п. 3д).

## Правило сети

Всё работает без сети; сеть — только для удобства (слово автора 25.11.2026: синхронизация через Google Диск, обновление) и никогда не
нужна, чтобы играть, записывать и смотреть статистику. Остальное — только по нажатию кнопки: поиск песни в MusicBrainz (`songinfo.js`), проверка часов (`clock.js`),
песни из Holyrics в своей сети (`holyrics.js`). Единственное исключение — проверка обновления раз в сутки
(`update.js`, режим «автоматически»). Политика страницы (`index.html`, `connect-src`) пропускает только свои
файлы, MusicBrainz, api.github.com и внутренний канал Tauri (`ipc:` — это не сеть, а связь окна с программой).
Аналитики, рекламы и трекеров нет; новая зависимость проверяется на скрытые обращения (`grep https://`).

## Файл `.melete`

`core/share.js`, формат — `docs/share-format.md`. Песни (название, исполнитель, тональность, темп, текст с аккордами),
их табы и ноты (по желанию — записи) и сет-лист. Личное **не отправляется**: выученность, текущий темп, метки,
время занятий. Принимается кнопкой «Принять файл» или открытием файла в Melete.

## Синхронизация телефона и компьютера

**Роли.** Компьютер (Windows/Linux) — сервер: посредник на Rust `src-tauri/src/sync.rs` принимает HTTPS на порту
53319 (Melete DEV — 53329) и передаёт запрос окну; всё решает JS-обработчик `sync.js: handleRequest`. Телефон —
клиент. В Melete DEV телефон тоже принимает подключения (`MeshServer.java`, плагин `Mesh`, тот же обработчик) —
связь всех со всеми.

**Сопряжение** — один раз. На компьютере включается «Связь с телефоном»: виден адрес и код из 6 цифр. Телефон
отправляет код (`/melete/v1/pair`), компьютер выдаёт ключ. Соединение — только TLS: у компьютера свой сертификат,
телефон **закрепляет его отпечаток** при сопряжении (`SyncHttpPlugin.java`) и дальше не отправит ключ никому другому.
Ключи сопряжения хранятся в `melete.sync` и в резервную копию не попадают.

**Что переносится.** Части копии `songs`, `profile`, `reading`, `calendar` — слиянием по `id` и `updatedAt`
(`data.md`). Файлы песен и медиатеки — кусками по 2 МБ (`/get`, `/put`), дорожки одной записи не задваиваются
(ключ «запись + часть + режим + версия»). Сведения, посчитанные позже (`ana`, `lyr`, привязки к песням), сливаются,
даже если файл уже есть на обоих (`/meta`, `/setmeta`). Удаления переносятся трёхсторонним сравнением: телефон помнит,
какие файлы были на обоих после прошлой синхронизации (`/delete`). Защита (аудит 13.11.2026): список стороны, у которой
база файлов не открылась (`files.noDb`, в ответе `/sync` — `noDb`), или пустой список при непустом прошлом — это
«недоступно», а не «удалено всё»: удалений нет ни в одну сторону (`planFiles`); список берётся после `files.ready`.
Профиль при синхронизации — только более свежий по времени правки (`profile.at`); пустой не затирает заполненный
(`applyParts(..., { fresh: true })`; при восстановлении копии — из копии, как раньше). **Настройки и оформление (с 28.11.2026) идут между своими устройствами** — часть `settings` в `SYNC_PARTS`, только для устройства с ролью `own` или без роли (`partsFor`, `settingssync.js: isOwn`). Слияние — по ключу верхнего уровня со временем правки (`settings.__at`, отпечаток значения — `settings.__sig`; `store.write` проставляет время при любой записи, `stampSettings`); позднее побеждает, равное — одинаково на обеих сторонах, удаление ключа — тоже правка; статистика модулей (`ear`, `beat`, журнал дней `vocal.log`) объединяется, а не перезаписывается. Идут только ключи белого списка `SYNC_SETTINGS`; `DEVICE_ONLY` (ключи и токены, Google, сопряжения, адреса, железо звука, размер интерфейса, фон, «считать на компьютере», метки миграций, этот экран) и запрещённые шаблоны `FORBIDDEN` — никогда, даже если имя попало в белый список (тест `tests/settingssync.test.js`; новый ключ без решения «ходит / не ходит» краснит тест). На проводе настройки — отдельное поле `data.sset` ({ values, at }), а не `parts`: прежние версии его не знают и настроек не трогают. Перед первым слиянием — копия `snapshots.take('sync')` (не вышла — настройки в этот раз не вливаются, остальное идёт). Настройки инструментов этого устройства (`practice.v1.tools`: уровни, раскладки окон, строй тюнера) не переносятся; свои пресеты (`settings.presets`) и данные модулей (`settings.<id>`) — переносятся. Ограничение: списки «целиком» (пресеты, рутины, сборники) — по времени правки ключа; две одновременные добавки на двух устройствах между обменами — побеждает поздняя (прежняя версия в копии на устройстве). Флаги инструкций (`help.js`) едут с частью `profile`: `settings.helpSeen` объединяется (отмечено на любом — отмечено везде), `settings.helpOff` — выключено, если выключено на любом (`backupparts.js: applyParts`). Команда пульта «открыть инструмент» (`app.showTool`) сперва закрывает настройки поверх.

**«Считать на компьютере»** (`settings.pcWork`). Телефон не делит свежие записи сам, а оставляет их компьютеру;
компьютер берёт записи телефона в свою фоновую очередь (в режиме, который просил телефон: `rec.want`), результат
приходит при следующей синхронизации. Фоновая синхронизация (`settings.syncAuto`) — только в тишине. Компьютера нет
дольше суток — телефон считает сам (**кроме дорожек 4/6 и улучшенного вокала: с 21.11.2026 их телефон не считает вообще**, только
ждёт компьютер — нагрев; DECISIONS 2026-11-21). Поэтому передача файлов и результата должна быть очень стабильной: возобновление при
обрыве, очередь, переживающая перезапуск, видимый статус — к исполнению. **Сделано 22.11.2026:** кусок файла (put/get) при обрыве повторяется трижды (`sync.js: RETRY_MS`, 1/3/8 с; ключ, режим, «занят» и остановка — без повторов; put безопасен — компьютер сам называет байт продолжения). Очередь после перезапуска и статус в плеере — ещё нет.

**Пульт** (`netctl.js`, DEV): сопряжённое устройство управляет звуком, метрономом, пэдами и плеером другого через тот
же защищённый канал (`/melete/v1/rc/*`). Пульт и синхронизацию базы можно включать по отдельности — «Режимы связи» ниже.

**Компьютер сменил адрес.** Роутер выдаёт адрес на время (DHCP), после перезагрузки компьютера он бывает другим —
для человека это выглядит как «компьютер забыл телефон». Не ответил по старому адресу — телефон сам обходит свою
сеть (`sync.js: nearAddrs`, `findMoved`: те же первые три числа, ближние номера первыми, 48 запросов разом, по 1,5 с
на соединение) и спрашивает `/hello` с закреплённым отпечатком: **ключ при поиске не уходит никому**, чужие
компьютеры отсеиваются на рукопожатии TLS. Нашёл — запоминает новый адрес и продолжает синхронизацию; в журнал —
«компьютер сменил адрес». Фоновая синхронизация ищет не чаще раза в полчаса (компьютер может быть просто выключен).
Устройства Melete DEV (связь всех со всеми) пока ищутся только по своему адресу. Надёжнее всего — закрепить за
компьютером адрес в роутере (резервирование DHCP).

Отладка: каждый отказ (незнакомый ключ, не тот отпечаток) пишется в журнал на обеих сторонах — отчёт о проблеме с
двух устройств обычно сразу показывает причину.

## Локальная связь идёт по Wi-Fi (28.11.2026)
Отчёт автора: «Failed to connect to /192.168.1.114 from /10.27.196.9» — Android вёл трафик приложения через **мобильную** сеть (Wi-Fi без интернета или «Wi-Fi+»), и адрес домашней сети был недостижим.
- **Привязка (`NetBind.java`):** соединения с частным адресом (10/8, 172.16/12, 192.168/16, 169.254/16) открываются через `Network` Wi-Fi (`Network.openConnection` — `SyncHttpPlugin`, синхронизация, поиск `/hello`; `Network.getSocketFactory` — `LinkPlugin.connect`, канал пульта). Только эти соединения: `bindProcessToNetwork` не используется, остальной трафик не меняется. Не частный адрес или Wi-Fi нет — прежнее поведение. Нужен `ACCESS_NETWORK_STATE` (добавлен в манифест). Сервер (`MeshServer`) слушает все интерфейсы — привязки не требует.
- **`src/core/netinfo.js`:** `netInfo()` → `{ wifi, cellular, ip }` (Android — плагин `NetInfo`; компьютер и веб — `wifi: true`, чтобы плашки не появлялись зря); чистые `isPrivateHost`, `bindFor` (зеркало `NetBind.forHost`), `noWifiFor`, `netLabel`.
- **Ошибки:** не дошли до локального адреса и `netInfo().wifi === false` — причина `nowifi` (`sy.err.nowifi`), а не «компьютер не найден» (поиск нового адреса при этом не запускается). В журнал `sync` к отказу дописывается сеть попытки («wifi», «только мобильная», «сети нет»); нативная ошибка несёт `[via wifi|default]` — по какому пути шло соединение. Так же в `pair` и `sendFile`.
- **Не проверено на телефоне** (Honor, Android 16): компилировалось по `android.jar` со заглушками Capacitor, логика — тестами `tests/netinfo.test.js`.
- **Аудит «компьютер или устройство»:** ручная синхронизация и «Отправить» идут по `opts.dev` к выбранному устройству; **фоновая** (`createSyncClient.tick`) и поиск смены адреса (`findMoved`, только `!opts.dev`) работают лишь с компьютером (`m.pc`) — сопряжённые телефоны (`m.devs`) в фоне не синхронизируются и после смены адреса сами не находятся. Это не ошибка кода, а недоделка: решение автора.
## Экран «Устройства» (с 28.11.2026)

Страница «Связь» настроек (`panel.js: linkHTML`) целиком строится в `screens/devices.js` (стили — `styles/devices.css`); `panel.js` лишь передаёт ей блоки
раздач (`sections`) и отдаёт клики (`devicesClick`). Движок (`sync.js`, `linkmode.js`, сервер `Mesh`) не менялся — те же `pair`, `syncNow`, `setLinkMode`, `forget*`.
- **Карточки** (`devicesOf`): компьютер телефона (`pcOf`), «Мои устройства» (`devsOf`), подключившиеся к этому устройству (`syncSrv.peers`, `mesh.peers`; у них нет адреса — только режимы и «Забыть»).
  Статус (`statusOf`) — по последнему обмену и последней ошибке без опроса сети: ошибка новее обмена и свежее 6 ч (причины unreachable/key/pin/off/tls/addr/repair) — «не отвечает»; обмен до 2 ч — «на связи»; иначе «давно не было»; обмена не было — «ещё не обменивались». Ошибки и явные проверки помнятся в памяти страницы (`errs`, `okAt`).
- **Проверить связь:** один `/melete/v1/hello` с закреплённым отпечатком (ключ не уходит); подробный замер — прежний `linkcheck.js` (DEV).
- **Мастер:** `waysOf` решает, что доступно на этом устройстве (телефон обычной версии — только «к компьютеру»; DEV и компьютер — ещё «показать код» / «подключиться к телефону»); шаг «показать» включает приём (`start()`), ждёт нового подключившегося через `subscribe`; шаг «подключиться» — QR (`scanQR`) или адрес и код; `sameNet` предупреждает, если адрес из другой сети (дом и мобильный интернет).
- **Сеть:** `core/netinfo.js` (`netInfo() → { wifi, cellular, ip }`, пишет другая работа) подключается через `import.meta.glob` — нет файла, нет плашки «Нет Wi-Fi», всё остальное работает.
- **Проверка:** `tests/devices.test.js`, `tests/e2e/devices.spec.js`.

## Режимы связи

С 18.11.2026 у каждого сопряжённого устройства два независимых переключателя (`core/linkmode.js`, страница «Связь»):
**«Пульт»** — команды и события (`/melete/v1/rc/*`: звук, метроном, пэды, плеер, открыть инструмент), база не затрагивается;
**«Синхронизация базы»** — песни, профиль (занятия и часы), чтение, календарь и файлы (`/sync`, `/get`, `/put`, `/meta`,
`/setmeta`, `/delete`). Можно оба; оба выключить нельзя (второй включится сам). Настройки и оформление не переносятся ни в
одном режиме.

- **Где хранится.** В `melete.sync` у записи устройства: `peers[ключ].mode` (компьютер и телефон DEV — подключившиеся к ним),
  `pc.mode` (телефон — его компьютер), `devs[адрес].mode` («Мои устройства»). Нет поля `mode` — включено всё: старые сопряжения
  ведут себя как раньше. `modeOf(entry)` даёт `{ rc, sync }` с этими умолчаниями.
- **Кто проверяет.** Обе стороны. Принимающая (`sync.js: handleRequest`) отвечает `403 { error: 'mode' }` на путь выключенного
  режима (в журнал — раз в минуту); начинающая (`syncNow`) не отправляет ни одного запроса, если у неё режим «Синхронизация»
  выключен (`reason: 'mode'`, строка `sy.err.mode`). Пульт на стороне телефона скрыт кнопкой, а при отказе показывает `rc.err.mode`.
- **Фон.** `createSyncClient.tick` в режиме «только Пульт» ничего не делает (`settings.syncAuto` не ведёт в обход режима), и
  `waits()` не ждёт от компьютера дорожек и разбора — их там не будет.
- **Исключения.** `/put` с `meta.sent` (кнопка «Отправить на устройство») и `meta.ens` (ансамбль) проходят в любом режиме — это явное
  действие человека, а не обмен базой; сопряжение, `/hello`, `/ens` — вне режимов.
- **Что видно человеку.** Под именем устройства — «пульт и синхронизация» / «только пульт» / «только синхронизация»; два
  переключателя с описанием (`lm.*`); подпись внизу страницы — что переносится (`lm.what`), в «только Пульт» — `lm.rcOnly`.
- **Проверка.** `tests/linkmode.test.js` (чистая логика, компьютер и телефон через общий обработчик, фоновый тик).

## Роли доступа (28.11.2026)

Над режимами — роль устройства (`core/roles.js`, чистые функции; слово автора 28.11.2026, проект — `docs/ecosystem.md`). Режимы стали
производными от роли: `modeOf(entry)` = сохранённые переключатели ∩ `roleToMode(роль)`; нет роли — `own`, старые сопряжения не меняются.

| Роль | Путь, который разрешён | Режимы |
|---|---|---|
| `own` «Моё устройство» | всё: `/sync /get /meta /setmeta /delete /put /ens /rc/* /ts/* /view /me` | rc + sync |
| `receive` «Приёмник песен» | только `/put` с `meta.sent === true` (и `/me`) | — |
| `control` «Пульт» | только `/rc/*` (и `/me`) | rc |
| `view` «Зритель» | только `/view` (и `/me`) | — |

- **Кто назначает.** Принимающая сторона, не клиент. Тот, кто показывает код/QR, выбирает роль в мастере («Показать код» → шаг «Что
  разрешить новому устройству?», по умолчанию — «Моё устройство» только для старых путей без мастера). Выбор лежит у него в памяти
  (`createSyncServer.setPairRole`), в QR и код **не кладётся**; в `handleRequest` на `/pair` роль берёт `ctx.pairRole()`, поле `role` из тела
  запроса не читается вовсе — подменить нечем. Запись: `peers[ключ].role`. Код с ролью не `own` одноразовый: после сопряжения он меняется
  (`rolePaired`), роль сбрасывается в `own`; закрытие мастера тоже сбрасывает выбор. Чужой, подсмотревший код, получает только то, что
  выбрал хозяин, и только один раз.
- **Проверка.** `handleRequest` после проверки ключа, до режимов, на **каждом** запросе: `roleAllows(role, path, json)`; отказ — `403 { error:
  'role' }`, в журнал раз в минуту на ключ и путь. Роль берётся из записи при каждом запросе, смена действует сразу. Неизвестный путь — только
  `own`; неизвестное значение `role` в записи — как `view` (самое узкое). `GET /melete/v1/me` → `{ role }` — любой роли.
- **Смена и отзыв.** Шторка устройства на принимающей стороне: показ роли и «Сделать …» (`setRole`), «Забыть» — отзыв. У начинающей стороны роль
  только показывается (`pc.myRole` / `devs[адрес].myRole`: пришла в ответе на сопряжение, обновляется `refreshMyRole` — «Проверить связь»).
- **Начинающая сторона не шлёт запрещённое.** `modeOf` учитывает `myRole` (кнопки «Синхронизировать» и «Пульт» не показываются, фон и `syncNow`
  не стучатся); `sendFile` и список «На устройство…» (`sendto.js`) пропускают только роли `own` и `receive`. Отказ с чужой стороны всё равно
  приходит как `reason: 'mode'`.
- **«Зритель».** У mesh не было read-only пути, добавлен `GET /melete/v1/view` (`guest.js: viewOf`): без `id` — список песен (карточки без
  файлов) и сет-листы; с `id` — одна песня (текст, тональность, темп, каподастр). Личное (занятия, профиль, календарь, настройки, файлы) не
  отдаётся. Экрана-«зрителя» на стороне подключившегося пока нет — путь и роль готовы; гостевая раздача по ссылке/QR (`guest.js`, браузер)
  остаётся отдельной и от ролей не зависит.
- **Тесты.** `tests/roles.test.js` (таблица роль × путь, 403 для каждой запрещённой пары, умолчания, `pairRole`, `/me`, `sendFile`),
  `tests/linkmode.test.js`; e2e — `devices.spec.js` (шаг «роль» мастера).

## Компьютер в фоне

Сценарий (слово автора 18.11.2026): окно Melete на компьютере свёрнуто или спрятано, человек работает в другой программе, а
телефон-пульт рулит звуками. Только DEV, только компьютер (Tauri), настройка «Работа в фоне» (`settings.deskBg`, по умолчанию
выключена; `core/deskbg.js`, Rust — `src-tauri/src/bg.rs`).

- **Значок в области уведомлений.** Подсказка «Melete: пульт активен, устройств: N» (N — устройства, чей запрос пришёл за последние
  20 с; пульт опрашивает раз в секунду; считает `sync.js: createSyncServer.active`), меню: статус, «Показать окно», «Закрыть пульт».
  Статус обновляется раз в 10 с и при смене связи (`bg_tip`). Нет значка в системе (Linux без трея) — `bg_set` вернёт `false`, режим
  выключится сам: без значка окно было бы не вернуть.
- **Крестик.** Пока режим включён и значок есть, закрытие окна прячет его (`hide`), а не завершает программу; звук, сервер связи и
  занятие продолжаются. Выход — «Закрыть пульт» (обычное закрытие окна: обновление «при выходе» срабатывает). Выключили режим при
  спрятанном окне — окно возвращается. В настройках под переключателем — предупреждение об этом.
- **Окно не выходит вперёд.** Команды пульта (`netctl.js`) работают только внутри приложения: `app.showTool` открывает инструмент
  в окне, ни Rust, ни веб-часть не вызывают `show`/`set_focus`/`unminimize`/`requestUserAttention`; вперёд окно выводится только
  кликом по значку или пунктом его меню (`bg.rs: show_window`). Системных уведомлений нет. Тест `linkmode.test.js` сканирует
  исходники и краснеет, если такой вызов появился где-то ещё.
- **Звук не душится.** Флаги WebView2 (`tauri.conf.json`, `tauri.dev.conf.json`): `--disable-background-timer-throttling`,
  `--disable-renderer-backgrounding`, `--disable-backgrounding-occluded-windows`, `CalculateNativeWinOcclusion` и (с 18.11)
  `IntensiveWakeUpThrottling` (раз в минуту через 5 минут в фоне) и `UseEcoQoSForBackgroundProcess` (режим эффективности Windows для
  скрытого окна). Планировщики звука (`audio/clock.js`) идут из звукового потока (AudioWorklet), а не от `setTimeout`; отложенные
  паузы и отключения пульта выступления (`showdeck.js`) тоже на этих часах. Остаются на `setTimeout` только чистки узлов
  (отключение голосов через сотни миллисекунд), их задержка в фоне безвредна. WebKitGTK (Linux) отдельных флагов не имеет — звук
  там держат часы звука; **не проверено на живом Linux**.
- **Не проверено без устройства:** поведение значка и скрытого окна на Windows 10/11 и Linux (GNOME без расширения трея значка
  не покажет — режим выключится), звук при долгом (часы) скрытом окне.
## Канал событий

Melete DEV, `docs/link.md` (формат кадров, состояния, ошибки). Постоянное двустороннее соединение телефон → компьютер
для игры в реальном времени: запрос-ответ по HTTPS для этого медленный. Те же порт и TLS-шлюз, что у синхронизации:
сертификат компьютера, отпечаток закреплён при сопряжении (`SyncHttpPlugin.Pinned` — общий). После рукопожатия клиент шлёт
«MLNK» + версию, и шлюз (`sync.rs: bridge`) отдаёт соединение `link.rs`, а не `tiny_http`; прочие соединения идут как раньше.
Кадр — `[тип 1][длина 2][нагрузка ≤ 65535]`; `TCP_NODELAY`, keep-alive, пинг раз в 2 с, тишина 7 с (клиент) / 12 с (сервер) —
обрыв. Телефон: `LinkPlugin.java` (плагин `Link`, `WifiLock` малой задержки, кадры событием `frame`); компьютер: `link.rs`
(события окну `link-open` / `link-frame` / `link-close`, команды `link_enable` / `link_auth` / `link_send` / `link_close`;
права в `build.rs` и `capabilities/default.json`). Всё решает окно: `core/link.js` (рукопожатие, автопереподключение с паузами
0,25…8 с, пинг, часы, буфер), `linkclock.js` (сверка часов, как в NTP), `linkjitter.js` (буфер 15–40 мс), `linkframe.js`
(формат), `linkhub.js` (транспорты). Ключ в `HELLO` проверяет окно по `mem.peers`; до этого допускается один `HELLO` до 1 КБ
и 5 с. Приём включается вместе с «Связью с телефоном» (только DEV), открывается канал кнопкой в «Проверить связь»
(`screens/linkcheck.js`); там же замер связи — 50 запросов `/melete/v1/rc/ping` (`netctl.js`), математика — `linkstats.js`.
Пока канал открыт, `background.js` держит службу в фоне. Новых сетевых обращений нет: только свой компьютер в своей сети по кнопке.

## Учитель и ученик (25.11.2026, Melete DEV)
`core/classroom.js` (логика без DOM), экраны `screens/classpage.js` (учитель: «Ученики») и `screens/studentpage.js` (ученик: «Учитель», «Домашка»); режим и блокировка — `core/student.js` (`docs/teacher-student.md`).
* **Транспорт — готовая связь телефон ↔ телефон (Mesh, только DEV на Android, `sync.js: meshAvail`):** ученик включает приём и показывает QR (код + отпечаток, как у обычного сопряжения); учитель сканирует и сопрягается (`pair`), устройство попадает в `devsOf()`. Хук `ctx.paired` в `handleRequest`: **первый сопряжённый, пока открыто окно кода, становится учителем** (`settings.student.teacher = { key, name }`, код гасится); пока учитель есть, сопряжение закрыто (`ctx.pairBlocked`, ответ 403 `locked`). Сменить учителя можно только сняв блокировку кодом.
* **Маршруты `/melete/v1/ts/*`** (обрабатывает `classroom.js: tsHandle`; допущен только ключ учителя, остальным 403): `hello`, `report` (отчёт недели: занятия, песни и темп, отметки заданий — **без записей звука, заметок и кода блокировки**), `pack` (задания, открытые инструменты и уроки, заметка — заменяют прежние; отметки «выполнено» ученика сохраняются). Режим устройства (`linkmode.js`) на `ts` не действует.
* **Данные:** учитель — `settings.classroom.students[addr]` (задания, `open`, `lessons`, заметка, последний отчёт); ученик — `settings.student` (`tasks`, `open`, `openLessons`, `note`, `teacher`, `syncedAt`). Уроки «Гитары с нуля» без учителя открыты, с учителем — только открытые им (`lessonOpen`, `ctx.lessonLocked` в читалке); «Первые шаги» не запираются.
* **Задания-ссылки** (`kind`: `free`/`lesson`/`tool`/`song`, `ref`): урок открывает уроки курса до нужного (`openFor`), инструмент — сам инструмент, песня едет в пакете как обычный `.melete` JSON (`shareOf` → `applyShare`: `unpack`/`planImport`/`applyImport` из `share.js`, повтор по названию и исполнителю обновляет, а не множит). У ученика кнопка «Открыть» (`homeworkGo`). В пакете ещё `goal` — цель недели (`settings.goalMin`, 30–3000 мин).
* **Новое задание у ученика** — `app.notifyNew` (плашка и местное уведомление, свой канал «Melete · Учитель», `reminders.js: notifyNow`); повторная отправка того же пакета не уведомляет.
* **Отвязка:** `releaseStudent` шлёт `ts/bye` (ученик забывает учителя, окно сопряжения снова открывается) и удаляет запись; ученика нет в сети — он отвяжется кодом блокировки.
* **Учитель при открытии «Учеников»** тихо обновляет отчёты старше 5 минут (`classpage.js: autoPull`, только там, где есть Mesh); на главной учителя — сводка (`classCard`).
* **Сеть — только по нажатию кнопки** («Обновить отчёт», «Отправить ученику») и при открытии страницы «Ученики», в своей сети Wi-Fi. **Ученик сам учителя не ищет** (приём — только пока приложение ученика открыто): фонового поиска нет.
* **Проверено:** юнит-тесты и петля двух сторон через настоящий `handleRequest` (`tests/classroom.test.js`), e2e `classroom.spec.js`. **Не проверено на двух телефонах** (Mesh, QR, Wi-Fi), Java не менялась.
