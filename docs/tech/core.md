# Ядро и экраны

Как приложение собирается при запуске, как рисует экраны и как ведёт занятие. Данные — в `data.md`,
модули-инструменты — в `modules.md`.

## Запуск: объект `app`

`src/main.js` подключает стили, ставит режим компьютера (`ui/desk.js`), загружает язык и вызывает
`core/index.js: boot(root)`. `boot` выполняет шаги строго по порядку — порядок важен:

1. **Журнал и диагностика** (`log.js`, `diag.js`) — первыми, чтобы ошибки запуска тоже попали в журнал.
2. **Возврат после проверок** (`cleanup.js`) — до чтения данных.
3. **Хранилище** (`store.js`; проекты студии — своя база `projstore.js`, читается сразу после запуска) и **шаги
   формата данных** (`migrate.js`).
4. **Язык, палитра, тема** (`i18n`, `palettes.js`, `applyTheme`).
5. **Настройки устройства** (`device.js`) и их приведение к нынешнему виду.
6. **Звук** (`audio/index.js: createAudio`). Объекты создаются сразу, а `AudioContext` — на первом жесте
   (браузеры запрещают звук без жеста).
7. **Файлы** (`files.js`), **запись** (`recorder.js`; через 2,5 с — восстановление оборванной записи),
   обработки (`jobs.js`, `autostems.js`), пакеты моделей, MIDI.
8. **Сессия, активность, часы, напоминания**, затем папка, синхронизация, гостевой сервер, копии, обновление,
   «Что нового».

Результат — один объект **`app`** (`store`, `device`, `audio`, `files`, `rec`, `session`, `folder`, `syncCli`,
`updater`…). Экраны получают `app` целиком; модули — только `ctx` (`modules.md`). Тесты собирают `app` по частям:
почти каждая часть — `createX(зависимости)` без глобального состояния.

## Как рисуются экраны

Фреймворка нет — это осознанное решение (прототип написан так же, кода меньше, всё прозрачно):

- экран — функция, которая возвращает **строку HTML**; её вставляют в `innerHTML` контейнера;
- нажатия ловит **один обработчик на контейнер** (делегирование), действие определяет `data-`атрибут
  (`data-act="export"`, `data-snap="…"`);
- после изменения данных экран просто рисуется заново (`render()`); подписка — `store.subscribe`;
- всё, что приходит от человека (названия песен, тексты), проходит через `esc()` из `ui/index.js`.

Общие элементы (`ui/index.js`): шторка `sheet(render, init)` (снизу, закрывается жестом вниз, стек шторок),
`toast`, `confirm`, переключатель `sw`, сегменты `seg`, `snav` — заголовок шторки. Клавиатура пианино —
`ui/keyboard.js`, эквалайзер — `ui/eq.js`, панель эффектов — `ui/fxpanel.js`, удержание и перетаскивание —
`ui/hold.js`, жесты — `ui/gestures.js`.

Экраны ядра — `src/core/screens/`:

| Файл | Экран |
|---|---|
| `shell.js` | каркас: нижние вкладки (состав и порядок — в настройках), переходы, общие действия |
| `home.js` | главная: карточка недели (кольцо → дни и цель, числа и дни → статистика, камень → свой экран; кружки дней тремя оттенками по дневной норме — `dayTone`), учёба, панель «Сегодня» (события дня, цель на день — `core/todaygoal.js`), ряд «Свободная практика / Начать «название» + Свободно + Сцена», быстрый доступ значками, песни плоским списком, слово маскота; помодоро и чат — справа в шапке (25.11.2026) |
| `songs.js` | библиотека песен и карточка песни |
| `calendar.js`, `stage.js` | календарь; сет-лист и сцена (автопрокрутка, педаль). Сцена (`screens/stage.js`): без песен и событий (рабочий сет-лист `settings.stageWork`), метроном одной полосой, клавиши пэда с жестами дрона, «Звуки» (`showpads` + банки `device.show`), свои уровни (`settings.stageMix`, `mixer.override`), список песен с заметками (`item.note`, реакция `settings.stageTap`), панель табов (`screens/stagescore.js`, alphaTab без плеера) |
| `tools.js`, `arrange.js` | «Инструменты»; правка вкладок и порядка удержанием |
| `session.js`, `mixer.js`, `fx.js` | занятие с окнами; микшер сбоку; эффекты шины |
| `panel.js` | панель профиля: профиль, неделя (`plan.js` — расписание), статистика, настройки, данные |
| `onboard.js` | регистрация (одна страница) |
| `diag.js`, `selfcheck.js`, `report.js` | диагностика, самопроверка, отчёт о проблеме |
| `share.js`, `backupsheet.js`, `update.js`, `whatsnew.js` | обмен, копии, обновление, «Что нового» |

«Назад» на Android (`core/back.js`) закрывает верхнее: диалог → шторка → панель → окно → сессия (сворачивается) →
песня → первая вкладка → приложение сворачивается.

## Занятие (сессия)

Логика — `core/session.js` (чистые функции над объектом «активное занятие»), учёт признаков игры — `core/activity.js`,
экран — `screens/session.js`, раскладка окон — `core/workspace.js`.

- **Начало**: `createActive({ type, songId, tool, mode })`. Виды: свободное, по песне, в инструменте.
- **Время** считается отрезками: паузы и «вдали» (экран погас, а в строгом режиме время идти не должно) хранятся
  как `[от, до]`. Поэтому завершение «задним числом» (по последнему действию) вычитает ровно то, что нужно.
- **Признаки игры**: касания и клавиши (`touch`), звук приложения (`noteHeard`), по желанию — громкость микрофона
  (звук не записывается). Долго ничего — занятие спрашивает «ещё играете?» и при молчании завершается по последнему
  действию (`idleAction`).
- **Режим учёта**: обычный (при погашенном экране время идёт, пока что-то звучит) и строгий (только экран).
- **Конец**: `summarize` → `buildRecord` → `commitSession` (печать, запись, событие для напоминаний и маскота).
- **Инструмент вне занятия** тоже учитывается (`recordToolTime`), но время, уже засчитанное занятием или
  секундомером, второй раз не идёт (`stopwatch.js` вычитает пересечение).

**Занятия — набор 13.11.2026** (DECISIONS 2026-11-13, проверки — `tests/e2e/practice.spec.js`):
- *Разбор*: в конце три поля «Получилось / Не вышло / Дальше» → `rec.review` (и те же строки в `rec.note`);
  `lastNext` — «В прошлый раз: …» в начале следующего занятия того же рода (`.slast`).
- *«Перерыв?»*: `breakDue` (`settings.breakMin`, 50 по умолчанию, 0 — нет), отметка `a.brk`; полоска `.sbrk`.
- *План занятия*: `core/routine.js` (`settings.routines`, `slot.routine` в расписании), экраны — `screens/routine.js`
  (раздел на «Песнях», правка, выбор при начале); в занятии `a.routine` и полоса `#splan`, в записи — `rec.plan`.
- *Тихий вид*: 30 с без касаний — `.session.calm` (только прозрачность); `settings.calmView`.
- *Повторение репертуара*: `core/review.js` (интервалы 2→64 дня по истории), блок главной `review`, `.rvmark`.
- *Сравнение дублей*: `screens/compare.js` — две записи песни, А/Б через два узла громкости на шине `media`.
- *Отчёт для педагога*: `core/teacher.js` (`weekReport`) и `screens/teacher.js` (картинка на холсте, «Поделиться»).

**Раскладка окон** (`workspace.js`): `F` — весь экран, иначе две буквы — верх и низ: `H` половина, `Q` две
четверти, `S` две полосы. Отсюда четыре размера модуля: `full`, `half`, `quarter`, `strip`.

**Монолитный вид** (DECISIONS 2026-11-18, `settings.solidView`, по умолчанию включён; класс `.session.solid`, стили — конец
`ui/session.css`, токены `--ws-tone`, `--ws-line`, `--ws-hit`, `--ws-pad`, `--r-ctl` в `styles/tokens.css`): окна сессии — один
экран без рамок, карточек и подложек; граница — линия 1 px с ручкой посередине в полосе `--ws-hit` (жесты разделителя прежние),
окно в фокусе — едва заметный тон, шапка и нижняя панель — на том же фоне. Смена раскладки и листание анимируются
(`.ws[data-motion]`, при «уменьшить движение» — только прозрачность). **Листание между инструментами** (только в раскладке `F`,
не в «инструменте вне сессии», не в повороте): порядок — `dockGroups` (панель), `session.js: pageTool`; инструменты с `nav: 'none'`
пропускаются. Флаг `meta.nav` (`'swipe'` | `'edge'` | `'none'`), читает `modules.js: navOf` — сначала `meta.nav`, потом таблица
`NAV_OVERRIDE` (умолчания ядра), иначе `'swipe'`. `'swipe'` — смахивание по экрану через `gestures.js: pageSwipe` (в него
добавлен реестр `addPageSwipe`, второго слушателя нет), `'edge'` — `gestures.js: wideSwipe` (чистая логика — `wideDir`:
начало в крайних 12 % окна, путь ≥ 85 % ширины, ≤ 450 мс, наклон ≤ 25 %); от края экрана (24 px, у широкого 20 px) жест не
начинается — там «Назад» Android. Выключено `solidView` — листания тоже нет, окна как раньше.

**Раскладка сцены и пульта звукаря** (`ui/layout.js`, слова автора 22.11 и 25.11.2026). Один механизм на два экрана: `arrange(blocks, lay, { t, name })`
выдаёт блоки в порядке пользователя; `bindLayout(root, api, skip)` — правка. Обычный вид **заморожен**: разметка та же, что без правки (обёртка
`.lyb` с `display:contents` и переменной `--lz`), ни меню, ни перетаскивания. Правка включается удержанием блока и **только в тишине**
(`api.busy`: сцена — `S.playing`, метроном, пэд, `app.sounding()`; пульт — `ctx.sounding()`), иначе тост «Остановите звук». В правке (с 26.11.2026 — как окна свободной практики, без кнопок): блоки вплотную
(`.lyb.ed`), инструмент затемнён и размыт, поверх — название (`.lyn`); содержимое не нажимается и ничего не звучит (pointerdown, click внутри блока гасятся
в capture). Граница под блоком (`.lyh`) — размер (`--lz` 0,5–2,2, сосед сужается), между блоками пары (`.lyv`) — ширина; **удержать блок 0,3 с и перетащить** —
место (`moveTo`: до/после ряда, у бока одиночного блока — рядом; у края список прокручивается); **смахнуть вбок** — скрыть (последний блок скрыть нельзя);
«Как было», «Готово», внизу скрытые (касание возвращает). Жесты — `blockGesture` (вертикальная прокрутка за браузером, `touch-action: pan-y`). Данные — `lay = { order, hidden, size }`, `size[id]` — ступень `s|m|l` (старое) или число;
признак правки в данные не попадает (`WeakSet`). События управления забираются в capture-фазе, жесты экрана их не видят. Тесты: `tests/layout.test.js`,
e2e `layout.spec.js`. Не сделано: деление экрана на несколько окон рядом (колонки), правка в альбомной ориентации (сетка сцены другая).

**Размеры блоков сцены** (`ui/stagefit.css`, слово автора 26.11.2026). Принцип окон практики: чем меньше места, тем меньше второстепенного; остаётся самое нужное. Две оси.
Высота — `data-z` на `.lyb` (`layout.js: tierOf`): xs ≤ 0,65, s ≤ 0,9, m ≤ 1,25, l ≤ 1,7, xl. Ширина — `@container` у блока (`container-type: inline-size` на `.sgmain/.sgplayer/.sgtempo/.sgkw/.sgpads/.sgbar/.sgseek`;
условие считается по внутренней ширине без отступов; только в портрете — в альбомной сетке свои правила). Что уходит и в каком порядке:
| Блок | Мельче (высота xs) | Уже (ширина) |
|---|---|---|
| Текст и песни | текст; у песен без заметок | < 300 — без списка песен |
| Плеер | без времени и тональности записи | < 340 — без времени и тональности; < 220 — без названия и выбора записи, остаются ▶ и полоса |
| Метроном | одна широкая кнопка темпа (касание — старт/стоп, вверх-вниз — темп) | < 190 — без TAP; < 140 — без ± |
| Пэд: управление | без «Волны» | < 170 — без «Волны»; < 125 — без «Глайда»; < 95 — без «Арпа» (настройки остаются) |
| Клавиши пэда | ниже, тоньше рамка | 6 в ряд → 4 (< 260) → 3 (< 170) → 2 (< 120) |
| Пэды звуков | один ряд (ряды — границей) | столбцы 2 (< 300) → 1 (< 140) |
| Громкости и ▶ | без подписей, крутилки 34 px | < 360 — без подписей; < 280 — без «Клик» и «Медиа»; < 210 — только «Общая» и ▶ |
**Свои блоки пэдов** (слово автора 26.11.2026): «Драм-пэды и звуки» — размер блока задаёт **число рядов** (`layout.js: rowsFor`: < 0,75 → 1, < 1,25 → 2, < 1,75 → 3, дальше 4), плитки не сжимаются, а перестраиваются (8 пэдов: 2×4 → 1×8; столбцов не больше 8; пока тянется граница — `api.live`); какие пэды на сцене — удержать пэд → «Какие пады на сцене» (`settings.stagePads`, до 12).
«Пэд: управление» (`padfx`) — отдельный блок раскладки: арп, глайд, волна, настройки пэда; по умолчанию слева от метронома (`stageDefaults`: `pair.tempo = 0,48`; у старых видов блок встаёт перед метрономом один раз, `lay.v = 2`; «Как было» возвращает умолчание через `api.defaults`).
Крупно (ступени l, xl) в блоке появляются: громкость пэда, у включённого арпеджио — громкость, рисунок, ритм, у включённого глайдера — громкость, эхо, подвижность (`data-pfx`, пишут в `device.drone`, звук сразу).
Крупнее: шрифты и значки растут вместе с блоком (до 1,6–1,8×), крутилки не шире 17 % блока. Цели не мельче 34 px (клавиши и пэды ударных — 30 и 28 px).
Проверка: e2e `layout.spec.js` («размеры блоков») перебирает размеры 0,5…2,2 и узкие пары (25/50/75 %): ничего не вылезает из блока, нет кнопок мельче 24 px, главное (темп, ▶, клавиши, пэды, плеер) на месте.
Пульт звукаря получает `data-z` так же, но правил сжатия для него ещё нет.

**Минимальный размер окна** (DECISIONS 2026-11-14): `meta.minSize` инструмента; `workspace.js: fits, tooSmall, settle`, в сессии — `guarded` вокруг каждой правки раскладки (бросок, добавить окно, схемы, перестановка) и `limitFrac` для границы между окнами; `fixWS(…, minOf)` при открытии.

**Окна и их размер.** Размер окна (`full`, `half`, `quarter`, `strip`) — по его пикселям (`workspace.js: sizeOf`); кроме того
окно несёт `data-fit` — сколько кнопок в нём помещается по площади (`fitOf`: 1 — 1/8 экрана, 2 — четверть, 4 — половина).
Инструмент по нему прячет лишнее (метроном в четверти — только колесо, пианино — клавиши и октава). Телефон на боку
(и пианино, повёрнутое приложением, `.session.rot`): окна во всю ширину, панель инструментов — колонкой справа.
Проверка всех инструментов во всех размерах — `tests/e2e/screens.spec.js` (SCREENS=1), итог — `build/screens-report.mjs`.

**Вывод на другое устройство** (только dev, слово автора 18.11.2026; подробно — `docs/link.md`, «Интерфейс вывода»).
Единая шторка `screens/outputsheet.js: outputSheet` — из шапки сессии (кнопка «Вывод», `.sout`), сцены (`stage.js`) и
пульта выступления (`ctx.output`, `modules/show`); в окнах сессии — значок «уходит на другое устройство» (`.outbadge`,
`session.js: paintBadges`). Логика без DOM — `outputcats.js` (категории, порядок целей, подписи, состояние канала, ошибки),
слой вывода — `app.output` (одна точка, `core/index.js`; сейчас временный `outputstub.js`).

## Неделя, статистика, расписание, напоминания

- `stats.js` — чистые функции `(sessions, songs, settings, now) → данные экрана`; неделя с понедельника, местное время
  (`time.js`). «Ударный режим» — по **неделям**, а не дням (принцип: без давления).
  `weekPlan` — неделя с учётом перерывов расписания: дни перерыва не дни практики, цель меньше на их долю,
  неделя целиком в перерыве серию не рвёт.
- `schedule.js` — расписание как в Google Календаре: блоки от–до по дням недели, несколько в день, перерывы по датам,
  правка «только этот день»; экран — `screens/plan.js` на странице «Неделя».
- `reminders.js` — уведомления телефона на неделю вперёд из расписания; пересчитываются при запуске, смене настроек
  и после занятия. Тексты — `remindtexts.js` по характеру маскота; тихие часы.
- `calendar.js` — события (репетиции, уроки, концерты), повторы, раскладка, выгрузка `.ics`.
- `mastery.js` — самоцвет по часам практики в приложении (часы «до приложения» не считаются); `tama.js` — маскот
  на занятии.

## Языки

`src/i18n/`: `ru.json` (основной и запасной), `uz.json` (латиница), `en.json`; `el.json` — названия для вида «Минимал»
(греческий). Строки ядра — `t('key')`, множественное число — `tn('key', n)` (формы — массивом). У модуля — свой
словарь (`modules/<id>/i18n/*.json`), ему отдаётся `ctx.t`. Узбекский и английский грузятся отдельными файлами по выбору.

Правила: каждая строка интерфейса — ключом в трёх языках; тексты нейтральные, без «ты» и «вы»; в en и uz нет
кириллицы. Совпадение ключей проверяет `tests/i18nkeys.test.js`.

## Оформление

- `styles/tokens.css` — все цвета CSS-переменными (`--bg` фон, `--ink` текст, `--l2`/`--l3` приглушённое, `--fill`, `--cell`, `--sep`, `--tint`…); темы: светлая,
  тёмная, «Бумага», OLED. Цвета в коде стилей — только через переменные.
- `core/palettes.js` — у каждого инструмента свой оттенок; палитра задаёт, как оттенки выглядят.
- `styles/mono.css` — вид «Минимал» (`data-style="mono"`), `styles/desk.css` + `ui/desk.js` — режим компьютера
  (`html.desk`: навигация сверху полосой с названием, главная в две колонки; в сессии — своя полоса инструментов слева), `styles/motion.css` — движение.
- Порядок подключения стилей важен (`main.js`): общие → сессия → модули → движение → «Минимал».
- Размеры окна модуля — container queries, а не размер экрана.

## Компьютер для не-новичка: оболочка, «Сегодня», рабочая станция (28.11.2026)
Макеты автора («экран профи», холст 1440×900, «делай точь в точь»). Всё — только `html.desk` и только не «новичок» (`html.dpro`: `deskshell.js: deskPro` — компьютер, профиль не `beginner`, не «Минимал», не `toolsOnly`); телефон и новичок не меняются. Стили — `styles/desk-shell.css` (после `desk.css`; шкалы и токены, без новых `font-size` и `#hex`).
- **Оболочка** (`screens/deskshell.js`, создаётся в `shell.js`, `sync()` на каждой перерисовке): верхняя полоса `.dtop` (Μελέτη, вкладки Сегодня · Служение · Песни · Инструменты · Статистика, поиск Ctrl K, чип профиля вывода звука — `outRoute` + `audio/profiles.js`, «Помощник», «Настройки») и левая рельса `.drail` (78 px, значок + подпись 11 px) — `RAIL`: играть (метроном, тюнер, пианино, дрон, лупер, глайдер, терменвокс) · учить (слух, ритм, теория) · слушать и писать (медиатека, ноты, студия, диктофон, спектр) · таймер, Библия; только включённые (`isOn`; Библия — церковный режим). Зелёный значок — шина микшера звучит (`mixer.isActive`, раз в секунду, только пока окно видно); подсвечен — открытый инструмент (`.tview[data-tool]`) или окно в фокусе занятия. Клик → `app.showTool(id)`, т. е. как раньше (в занятии — в окно в фокусе). Прежняя полоса вкладок `.tabbar` остаётся в документе скрытой (Ctrl 1–9 читают порядок `.dtab`, тесты — `.tabbar`). «Служение» — вкладка «Календарь» (в церковном режиме подписана «Служение»; приложение светское); переназначить — `app.deskNav = { service: 'id вкладки' }` до первой отрисовки. Содержимое, слой занятия (`.session`), окно инструмента и настройки сдвинуты правее рельсы (`--rail`, `--top` = 56 px); значки в нижней панели занятия (`.sdock`) скрыты — их заменяет рельса.
- **«Сегодня»** (`screens/deskhome.js`; в `shell.js` вместо `homeHTML` при `dpro`): ближайшее событие с песнями (в церковном режиме — «служение»; сет-лист — песни события, «готова» = есть аккорды (`chordsIn`) и темп дошёл до цели), выбор 10/20/30/45 мин (`device.deskToday.min`) и «Начать» (Пробел) — обычный план занятия `desk-today` в `settings.routines` (разминка с метрономом, одна-две песни «подтянуть» с их темпом, свободная игра; сумма — ровно выбранное время; «Изменить план» открывает его в редакторе планов), «Свободно» (прежнее `data-act="free"`), «Продолжить» (последняя песня, «Рабочая станция», медиатека), репетиция сегодня, «подтянуть», неделя (`weekData`/`weekPlan`), помощник. Кнопки «Репетиция» (первая не готовая песня), «Сет-лист» (календарь), «На сцену» (`stagePick`) — временные привязки, их можно перенастроить, когда экран служения будет готов. Внизу — «Все блоки главной» (`view.classic`): прежняя главная целиком, там же «Центр управления» обратно. Модель — чистые `todayModel`, `planFor`, `planText` (тесты `tests/deskshell.test.js`).
- **Рабочая станция** (`screens/deskwork.js`; из «Продолжить» и поиска): обычное занятие + раскладка окон (`PRESETS`, пишется в `device.wsMap` той же сессии, правится как всегда) + полоса `.dmix` справа в слое занятия (`watchStation`: общая громкость `mixer.setMaster`, уровни метронома/пэда/лупера/пианино `mixer.set`, выключение звука, профиль вывода, сцены `scenes.js`: ←/→ по сценарию или по кругу, имя — окно сцен). Звук не трогается, кроме громкостей теми же вызовами, что у ползунков. Раскладки: «Занятие» — метроном + пэд сверху, клавиши снизу; «Репетиция» — ноты + метроном + пэд; «Запись» — метроном + пэд, лупер снизу. **Ограничение:** в окнах занятия при широком окне (клавиши, ноты — `meta.minSize: half`) помещается не больше трёх инструментов, поэтому не четыре панели макета; остальное — рельсой в окно в фокусе. Смена раскладки при идущем занятии пересоздаёт окна (`session.hide()` + `open()`) — как закрытие и открытие занятия, метроном и таймер занятия не прерываются.
