(Раздел «Интерфейс вывода» — выбор вывода в сессии. Остальные разделы — сопряжение, пульт, синхронизация — ведёт

## Интерфейс вывода

Слово автора 18.11.2026: управление другим устройством доступно **во всей сессии практики, сцене и пульте выступления**.
Человек в обычной сессии выбирает, куда выводить звук, метроном, плеер: на этот телефон, на сопряжённое устройство или
на оба сразу. Пульт — не отдельный экран, а те же окна и инструменты с выбором вывода. Только dev (`variants.js: DEV`);
по умолчанию везде «этот телефон» — без выбора ничего не меняется.

**Категории** (`outputcats.js: CATS`): `sound` — инструменты и звук (пианино, пэды, глайдер, терменвокс, лупер, студия),
`click` — метроном и сигналы, `media` — плеер и основной трек (медиатека, пульт выступления), `control` — громкости и
настройки. Не выводятся: Библия, вокал, ритм, тюнер, слух, учебник, спектр, конвертер (`CAT_OF` — инструмент → категория).
Выбор — по каждой категории отдельно, по умолчанию один общий («Всё на…»).

**Контракт слоя вывода** (`app.output`, одна точка в `core/index.js`; пока — `outputstub.js`, ничего не отправляет):

| Что | Смысл |
|---|---|
| `get(cat)` → `'local'`/`'remote'`/`'both'` | куда идёт категория |
| `set(cat, target)` | выбрать |
| `target` → `{ key, name, kind }` или `null` | выбранное сопряжённое устройство (`kind`: `pc` / `dev`) |
| `state` → `{ link: 'off'/'connecting'/'on', rtt, jitter }` | состояние канала |
| `subscribe(fn)` → отписка | изменения выбора и состояния |
| `ping?.()` → `Promise<{ ok, rtt }>` | «Проверить связь» (кнопки нет, если метода нет) |
| `mode(devKey)` → `{ control, sync }`, `setMode(devKey, patch)` | режимы «Пульт» и «Синхронизация базы» устройства (хранение — melete.sync, у настоящего слоя) |
| `setAll?(mode)`, `setTarget?(key)`, `candidates?()` | необязательные расширения: «Всё на…», выбор устройства при нескольких, список сопряжённых |

Если устройства нет (`target === null`), `get` обязан отдавать `'local'` (так делает адаптер); шторка не даёт выбрать
остальное и объясняет, как подключить. Нет связи — звук не должен пропадать: это забота слоя вывода.

**Где что.** Кнопка «Вывод» — в шапке сессии (значок, на широком экране ещё и цель; точка — состояние канала: серая —
нет связи, жёлтая — подключение или медленно, красная — плохо, зелёная — хорошо; задержка в мс — в шторке и на широкой
кнопке), на сцене — в верхней полосе, в пульте выступления — в шапке страниц. Касание — шторка, **удержание —
«Телефон ↔ Компьютер» для всего** (`quickSwap`). Шторка: «Всё на…» (этот телефон / компьютер `<имя>` / оба сразу),
устройство (если сопряжено несколько), связь с кнопкой «Проверить связь» и понятной ошибкой (`errorKey`: нет устройства,
нет связи, подключение, плохая связь, не отвечает), раскрывающийся список «По категориям». В окне инструмента, чей
вывод ушёл на другое устройство, — значок в левом верхнем углу (не перехватывает касаний; в окне во весь экран и в
«полосе» скрыт). Настройки → «Телефон и компьютер» → «Вывод и пульт»: у каждого сопряжённого устройства переключатели
«Пульт» и «Синхронизация базы» (`app.output.mode/setMode`).

**Как подключить настоящий слой.** `src/core/output.js` отдаёт тот же контракт; в `core/index.js` заменить
`createOutputStub(app)` на него (одна строка). Шторка и значки читают только `app.output`.

Проверка: `tests/outputcats.test.js` (порядок целей, подписи, состояние канала, ошибки, контракт адаптера),
`tests/e2e/output.spec.js` (шторка → «Оба сразу» → `get('sound') === 'both'`, по категориям, значки, удержание, без устройства).

## Вывод (DEV)

Режим «вывод на другое устройство» (слово автора 18.11.2026): играем на телефоне (пианино, глайдер, пэды, арпеджиатор,
метроном, плеер, звуки и фон пульта), а звук делает компьютер — его тяжёлые версии (полный рояль и т. п.). Для каждой
категории выбирается, куда давать сигнал. Только DEV (`core/variants.js: DEV`); по умолчанию везде `local` — без выбора
приложение работает как раньше.

### Контракт (имена не менять — на них опирается интерфейс)

- Категории: `'sound'` (ноты и звук инструментов: пианино, глайдер, пэды, арпеджиатор, дрон, звуки и фон пульта),
  `'click'` (метроном и сигналы), `'media'` (плеер медиатеки, основной трек пульта), `'control'` (громкости шин).
  Не участвуют: Библия, вокал, ритм, тюнер, слух, учебник, спектр, конвертер; шины `looper` и `notes` всегда у себя.
- Цели: `'local'` | `'remote'` (сопряжённое устройство, одно) | `'both'` (дублирование).
- `app.output.get(cat)` → цель; `app.output.set(cat, цель)` (хранится в `device.output`, не синхронизируется);
  `app.output.target = { key, name }` — какое устройство; `app.output.state` → `{ link: 'off'|'connecting'|'on', rtt, jitter }`;
  `app.output.subscribe(fn)`. `app.output.effective(cat)` — действующая цель с учётом связи (при обрыве — `local`).
- Транспорт подключается `app.output.attach(транспорт)` (`null` — отключить). Интерфейс транспорта:
  `{ send(frame), onFrame(fn) → off, connected, now(), state?, rtt?, jitter?, onState?(fn) → off, clock?: { toRemote, toLocal } }`.
  Переходник к `link.js` — `output.js: linkTransport(link, clock)` (JSON в байтах, тип `out`, glide — `out.l`).
  Предположения о `link.js`: `link.send(type, bytes)`, `link.onFrame(fn(type, bytes))`, `link.state`, `rtt`, `jitter`.

### События (кадр — объект `{ c, e, s, … }`; `s` — номер; `lossy: 1` — можно терять)

| c | e | что |
|---|---|---|
| sound | `on` / `off` / `rel` / `all` | нота: `k` ключ, `i` шина, `m` нота, `v` сила, `pt` звук, `at` метка (время отправителя, с) |
| sound | `pad+` / `pad-` / `padv` / `padx` | пэд: настройки `set` (весь `device.drone`, арпеджиатор внутри), `over` (созвучие), громкость, посыл |
| sound | `pk+` / `pk-` | клавиши пэдов (режим пианино) |
| sound | `g` / `g-` | glide: непрерывное управление (`i` голос, `p` параметры); `g` — `lossy`, «последний побеждает» по `s` |
| click | `m+` / `m-` / `mb` / `chime` | метроном: `cfg` целиком и метка начала `at`, темп `bpm`; сигнал окончания |
| control | `mix` | громкость и выключение шины: `b`, `v`, `m` |
| sound, media | `x` | команда общему движку: `n` имя, `f` метод, `a` аргументы (пады, фон и трек пульта, плеер) |
| media, sound | `halt` | заглушить движки категории (цель вернули на `local`) |
| sync | `sync` | полный снимок: звучащие ноты, пэд, клавиши, метроном и его настройки, громкости |
| bye | `bye` | отпустить всё от этого устройства |

Арпеджиатор не пересылается нотами: на принимающей стороне он играет сам — по присланным настройкам пэда. Поэтому у
передающего при `remote` арпеджиатор молчит (`drone.local.on === false`), а при `both` играют оба независимо.
Ноты с узлом назначения (`opts.out`, это арпеджиатор) остаются у себя.

### Передающая сторона (`core/output-hooks.js`)

- `local` — вызов оригинала напрямую. `remote` — событие в канал, у себя не играется (ни голосов, ни CPU).
  `both` — и туда, и сюда; местная копия сдвинута на `bothDelay` (линейка компенсации — чистая функция): часы не сведены —
  полпути (`rtt/2`) плюс буфер дрожания, сведены — только буфер.
- Пэды при `remote`: «звучит у них» — тень (`output.sh`); `drone.on`, `sounding`, `held`, `chord` её учитывают, окна и
  арпеджиатор перечитывают состояние через `drone.notify()`.
- Метроном при `remote`: у себя идёт (экран, вспышка, вибрация, счёт темпа), но пишет в тупиковый узел шины — звука нет;
  там запускается с меткой начала. `metro.start(at)` принимает время первого удара.
- Микшер (`control`): значение всегда пишется и у себя (интерфейс показывает правду), при `remote` / `both` ещё и уходит.
- Любая ошибка отправки гасится: звук у себя не страдает.
- Общие движки: `output.share(cat, имя, движок, [методы], { ret, drop })` — методы движка уходят по цели категории, на другом
  конце вызываются оригиналы. Подключено: пульт выступления (`show.pads`, `show.bed` — `sound`; `show.deck` — `media`).
  Плеер медиатеки подключается так же — вызовом `share('media', 'player', …)`.
- Glide: `output.glide(id, params)` (≤ 1 кадра в 16 мс, `true` — ушло и локально играть не надо), `output.glideEnd(id)`,
  принимающий — `output.onGlide(fn(id, params, end))`. Каркас: движок глайдера не подключён.

### Принимающая сторона

- Нота: `at` → местные часы (`linkclock.toLocal`) + буфер дрожания (`jitterBuffer`); часы не сведены — приход + буфер.
  Опоздавшее больше чем на 0,6 с не играется; отпускание выполняется всегда. Ключи голосов — с префиксом `~`;
  не больше 32 удалённых голосов (лишние вытесняют старые); шины — только из категории `sound`.
- Пэд, метроном, громкости: присланные настройки применяются **в памяти** (не на диск), свои запоминаются и возвращаются
  при отпускании. Ключи `__proto__` и т. п. отбрасываются.
- Ошибка обработчика одного кадра не роняет остальные (в журнал через `report`).

### Обрыв канала

- Принимающий (`state` не `on`, `bye` или смена транспорта): немедленно отпускает все удалённые голоса (быстро), пэды
  и клавиши (плавное затухание 0,8 с), метроном, глушит общие движки (`drop`), возвращает свои настройки и громкости.
  Обрыв замечается по `onState` и по проверке раз в секунду (транспорт мог не сообщить).
- Передающий (запасной ход, `output.failover`, по умолчанию включён): пока связи нет, цель действует как `local`; пэд и
  метроном, что играли «у них», продолжаются у себя; новые ноты звучат у себя. Тишина на сцене дороже.
- Подключение или возврат связи: передающий шлёт `sync`; принимающий приводит состояние к присланному (лишнее отпускает).
- Смена цели на ходу переносит звучащее: `local → remote` — пэд и метроном уезжают, `remote → local` — возвращаются.

### Не сделано / ограничения

- Файлы: пады, фон и треки пульта ссылаются на файлы медиатеки; на другом устройстве их нет — перенос файлов (по запросу,
  кешем) нужен транспорту. Без файла движок отвечает ошибкой, как при потерянном файле.
- На принимающем устройстве модуль `show` должен быть открыт (движки создаёт модуль); безголовые движки — следующий шаг.
- Плеер медиатеки, глайдер, тюнер-тон (`refTone`): точек подключения нет или это каркас. Бинарное сжатие кадров — позже.
- Задержка выхода принимающего (`outputLatency`) в оценку не входит. Метка `at` у метронома игнорируется без сведённых часов.
- Проверено только на петле в памяти (`tests/output.test.js`); на двух устройствах и на слух не проверено.
# Канал событий (Melete DEV)

Постоянное двустороннее соединение телефон ↔ компьютер для игры в реальном времени: телефон играет (пианино, глайдер,
пэды), звук и тяжёлые версии инструментов — на компьютере. Запрос-ответ по HTTPS (`sync.js`, пульт `netctl.js`)
для этого медленный: каждый запрос — новый круг и опрос раз в секунду. Канал держит одно длинное соединение и шлёт
маленькие двоичные кадры сразу.

Только **DEV** (`variants.js: DEV`) и только **по кнопке** (Настройки → Связь → «Проверить связь» → «Держать канал
открытым»; на компьютере — включённая «Связь с телефоном»). Существующая синхронизация и пульт-шторка не менялись.
Решения и устройство — `docs/tech/connect.md`, раздел «Канал событий».

## Соединение

1. Телефон открывает TCP на порт синхронизации компьютера (53319, у DEV — 53329) с `TCP_NODELAY` и keep-alive и
   проходит рукопожатие TLS. Отпечаток сертификата сверяется с закреплённым при сопряжении (`LinkPlugin.java`
   использует тот же `SyncHttpPlugin.Pinned`); не совпал — отказ `pin`.
2. Первые 5 байт открытого текста — **преамбула**: `4D 4C 4E 4B` («MLNK») и версия `01`. Шлюз компьютера по ним
   отличает канал от HTTP (`sync.rs: bridge` → `link::first_bytes`, `link::is_link`); всё прочее идёт к `tiny_http`, как раньше.
3. Дальше в обе стороны — кадры. Первый кадр клиента — `HELLO` с ключом сопряжения (тем же, что `X-Melete-Key`).

## Кадр

```
[тип: 1 байт][длина нагрузки: 2 байта, старший первым][нагрузка: 0…65535 байт]
```

Тип 0 недопустим (повреждённый поток — соединение закрывают). Крупное (файлы) по каналу не идёт — только по HTTPS.

| Тип | Имя | Нагрузка |
|---|---|---|
| `0x01` | HELLO | JSON `{ v, key, name }` — клиент → сервер, первым |
| `0x02` | WELCOME | JSON `{ v, name }` — ответ сервера, канал открыт |
| `0x03` | ERROR | JSON `{ code }`, дальше соединение закрывается |
| `0x04` | PING | `seq` u32 + `t0` float64 (мс на часах отправителя) — 12 байт |
| `0x05` | PONG | `seq` u32 + `t0` + `t1` (получил) + `t2` (ответил), float64 — 28 байт |
| `0x06` | BYE | пусто — закрываю |
| `0x07–0x1F` | — | зарезервированы |
| `0x20–0x7F` | событие | метка времени отправителя float64 (мс) + данные приложения |
| `0x80–0xFE` | сырой | данные приложения как есть |
| `0xFF` | — | зарезервирован |

Числа — big-endian. «Мс на часах отправителя» — `performance.timeOrigin + performance.now()`.
Событие `0x20–0x7F` приёмник получает с пересчитанным временем: `link.onEvent(fn(type, data, { ts, at, late, delay }))`,
где `at` — когда играть у себя (свои часы, мс: время события + пол + буфер дрожания), `late` — на сколько кадр опоздал
(0 — вовремя), `delay` — запаздывание кадра относительно его времени. Для «сырых» кадров — только `link.onFrame(fn(type, payload))`
(его получают и события, нагрузкой как есть).

## Состояния и ошибки

Состояния `link.state`: `idle` (закрыт) → `connecting` → `open`; обрыв → `retry` (ждёт и пробует снова) ; `failed` (повтор
бесполезен — нужно действие человека).

Автопереподключение (только клиент): паузы 0,25 → 0,5 → 1 → 2 → 4 → 8 с и дальше 8 с (с разбросом до 20 %),
сбрасываются при открытии. Пинг каждые 2 с; тишина дольше 7 с — соединение считается мёртвым и закрывается;
рукопожатие — не дольше 5 с.

| Код (`link.error`) | Откуда | Повтор | Что делать |
|---|---|---|---|
| `key` | компьютер не знает ключ | нет | подключить заново (сопряжение) |
| `pin` | сертификат не тот | нет | подключить заново |
| `version` | версии не совпали | нет | обновить приложение |
| `busy` | зарезервирован | нет | — |
| `net` | сеть, порт закрыт | да | — |
| `tls` | сбой рукопожатия | да | — |
| `timeout` | нет рукопожатия / тишина 7 с | да | — |
| `proto` | сломанный кадр, лишний кадр до проверки | да | — |
| `off` | компьютер выключил приём | да | — |
| `closed` | закрыли сами или `BYE` | нет | — |

## Защита (компьютер, `link.rs`)

- Приём выключен, пока окно не включит его командой `link_enable` (DEV, при включённой «Связи с телефоном»); выключили —
  все соединения закрываются.
- До ответа окна «ключ верный» (`link_auth`) допускается ровно один кадр `HELLO` до 1 КБ и 5 секунд; иное — закрытие.
  Ключ проверяет окно (`mem.peers`, как `handleRequest`); неверный — `ERROR key`, закрытие.
- После проверки — тишина дольше 12 с закрывает соединение.
- Запись — отдельным потоком из очереди: `link_send` только ставит кадр в очередь, порядок сохраняется.

## Часы

PING/PONG несут `t0 t1 t2`; получатель считает `t3` и по каждому обмену — круг `rtt = (t3−t0) − (t2−t1)` и сдвиг
`offset = ((t1−t0) + (t2−t3))/2` (на сколько часы другого устройства впереди). Последние 16 обменов; берётся медиана сдвигов
лучших 8 (по кругу). Сразу после открытия — 16 обменов подряд через 60 мс, потом пинг раз в 2 с. Готовность — от 4 обменов.
`link.clock.toRemote(мойЧас)` / `toLocal(чужойЧас)`; дрейф кварцев (десятки мс за минуты) гасится постоянным
обновлением.

## Буфер дрожания

Кадр опоздал на `d = прибытие − время события`. Минимум `d` за 64 кадра — «пол» (путь без очереди + ошибка часов), всё сверх
пола — дрожание. Буфер = 95-й процентиль дрожания + 4 мс, в границах **15–40 мс**: растёт сразу, убывает медленно (2 % шага).
Играть: `время события + пол + буфер`; опоздавший кадр играется немедленно и считается (`jitter.stats().late`). Границы —
`createLink({ jitter: { min, max } })`.

## Проверка связи

«Проверить связь» (Настройки → Связь, рядом с компьютером и «Моими устройствами»): 50 запросов `POST /melete/v1/rc/ping`
по одному (пауза 30 мс, таймаут 2 с) по обычному защищённому каналу. Показано: медиана, 95 % быстрее, худший, потери,
разброс (среднее изменение между соседними ответами) и вывод:

| Вывод | Условие |
|---|---|
| `great` — хватает и для быстрой игры на пианино | p95 ≤ 30 мс, потерь нет |
| `ok` — пэды и аккорды хватает, быстрая игра на пределе | p95 ≤ 70 мс, потери ≤ 2 % |
| `poor` — только медленное | p95 ≤ 150 мс, потери ≤ 5 % |
| `bad` — нестабильно | иначе |
| `none` — нет ответов | |

Замер по HTTPS включает накладные расходы запроса: канал событий быстрее. Для канала — `link.ping()` (круг одного обмена).

## Android: Wi-Fi и фон

Пока канал открыт, `LinkPlugin` держит `WifiLock`: `WIFI_MODE_FULL_LOW_LATENCY` (Android 10+; действует при включённом
экране и приложении на виду), иначе `FULL_HIGH_PERF`. Права — `WAKE_LOCK` (уже есть в манифесте, новых нет).
Работа в фоне: пока канал открыт, `background.js: busyText` возвращает «Открыт канал с компьютером» — работает служба
`KeepAliveService`, Android не замораживает приложение.
